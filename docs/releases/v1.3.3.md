Directly opens Instagram straight into your DMs and takes away the feed, Reels and Explore. Watch the
reel a friend sent, then stop.

A diagnostics build, so the phone can answer what the code cannot. Nothing about routing changed —
this release exists to see what 1.3.2 does on your device.

**The Lock screen now records what the app decided, and can copy it out.** A phone has no console, so
a bug that only happens on a device leaves one kind of evidence: your memory of what the screen did.
With **Debug logging** on, the Lock screen's Diagnostics card lists the last 50 decisions newest-first —
each document load, every route the page reported, every tab tap and whether it landed, every link's
verdict (`allow`, `block`, `browser`, `meta`, `frame`), the account and unread reports, and any load
error — each with the time it happened, as `20:01:03 block www.instagram.com/reels ` plus the reason.
**Copy diagnostics** puts the same list, with the version, platform, iOS version and current path, on
the clipboard in one piece.

- Only routes, verdicts and link hosts are recorded. A link's query string is dropped before anything
  is stored, and the page protocol has no field for message text, so nothing said in a DM can appear
  there. A **Clear** button starts a fresh log when you reproduce something.
- **`frame` is the line to look for** on the Safari problem: it marks a subframe request the app
  ignored instead of acting on. If Safari still opens while the log's last line for that moment is a
  `load` that never reaches a `route`, the page navigated itself somewhere the guard could not see.
- **`tap activity` followed by `tab-failed`** is Instagram sending the tap back to the inbox; `tap
  activity` followed by `route /accounts/activity` means it opened and the tab was fine. Between the
  two, the log says which.
- Entries live in memory only and are gone when the app is closed. They are held whether the switch is
  on or off — the switch decides what is shown and copied, so turning it on after something went wrong
  still shows the run-up.

## What this build cannot do

- **Facebook sign-in.** Not a limitation Directly can lift: the session would have to land in Safari's
  cookie store, which this app never sees. Use your Instagram username and password.
- **No alerts while the app is closed.** A `WKWebView` cannot receive web push, so a banner appears
  only while Directly is running. Background alerts would mean a server holding your session.
- **No instant switching between stored accounts.** One web view, one cookie jar, one session.

## Android

1. Download the APK on the phone, or transfer it there.
2. Allow installs from the browser or file manager when Android asks.
3. Install. Package `com.directly.app`, version 1.3.3, versionCode 7, target SDK 36.

Signed with the Android debug key, which is what makes sideloading possible. That is not a Play Store
upload key, so this build will never arrive through the Play Store.

## iOS

The IPA is built with `CODE_SIGNING_ALLOWED=NO`: a real `arm64` device binary with no signature,
because a certificate does not belong in CI. iOS refuses to install it until it carries a signature
from a team the device trusts.

**A. Sign it on your Mac** — needs a Development or Ad Hoc profile that already lists the device:

```bash
tools/resign-ipa.sh ~/Downloads/directly-v1.3.3-unsigned.ipa \
  --profile ~/Downloads/Directly.mobileprovision \
  --device 00008110-000A1B2C3D4E5F60
```

It checks the bundle id, team, profile expiry and the device UDID against the profile before touching
anything, signs nested code deepest-first, verifies each item and the finished bundle, then installs
with `devicectl` (Developer Mode must be on). `--dry-run` prints the plan and signs nothing.

**B. Sideloadly or AltStore** — drag the IPA in, enter your Apple ID, choose your team. A free
account's profile expires after 7 days, after which the app refuses to launch until it is signed
again; AltStore can refresh on a schedule, Sideloadly cannot.

## Notes

- The log is the point of this release, so it is worth turning on before you reproduce: Lock → What you
  keep → **Debug logging**.
- The Diagnostics card only claims what it can see. `unread unknown` still means no inbox link was
  read on the page, which is a selector fact rather than a message count.
- The DM badge and the alert are local. Nothing arrives while the app is closed.
- A reel opened from a conversation stays on that reel; swiping up or pressing next does nothing.
- Independent project, not affiliated with Instagram or Meta.
