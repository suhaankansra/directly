Directly opens Instagram straight into your DMs and takes away the feed, Reels and Explore. Watch the
reel a friend sent, then stop.

This release adds the two things people asked for, each as far as a web view can honestly take them —
and says where that line is instead of pretending it isn't there.

**Alerts you can control.** New DMs already raised a banner and an app-icon badge; there was no way to
turn them off, and nothing explained when they arrive. The Lock tab now has **Alerts → New messages**.
Turning it on asks the system for permission, turning it off clears the banner and the badge, and if
you have already refused in your device settings the switch says so instead of pretending to work.

**Switch account.** **Lock → Account → Switch account** opens Instagram's own account menu — the
chevron at the top of the page, which our tab bar had made unreachable. Instagram's switcher is the
only one that exists here: a second account lives in the same session, exactly as it does on the web,
and Directly never stores a login of its own.

**The version footer no longer lies.** If you came from 0.2.0, the Lock screen and the Copy
diagnostics report said `0.1.0` regardless of build; that number is now read from the build itself.

## What this build cannot do

Worth knowing before you install, because other apps do offer it:

- **No alerts while the app is closed.** A `WKWebView` cannot receive web push — no service worker
  runs in it — so a banner appears only while Directly is running. The icon badge is the only thing
  that persists. Background alerts would mean a server holding your Instagram session; this app
  exists so that no server has one.
- **No instant switching between stored accounts.** One web view, one cookie jar, one session.
- Instagram's own switcher has to be on screen for the button to work. When it isn't, Directly says
  `Instagram’s account menu isn’t on this screen` rather than doing nothing.

## Android

1. Download the APK on the phone, or transfer it there.
2. Allow installs from the browser or file manager when Android asks.
3. Install. Package `com.directly.app`, version 1.3.0, versionCode 4, target SDK 36.

It is signed with the Android debug key, which is what makes sideloading possible. That is not a
Play Store upload key, so this build will never arrive through the Play Store.

## iOS

The IPA is built with `CODE_SIGNING_ALLOWED=NO`: a real `arm64` device binary with no signature,
because a certificate does not belong in CI. iOS refuses to install it until it carries a signature
from a team the device trusts. Two ways:

**A. Sign it on your Mac** — needs a Development or Ad Hoc profile that already lists the device:

```bash
tools/resign-ipa.sh ~/Downloads/directly-v1.3.0-unsigned.ipa \
  --profile ~/Downloads/Directly.mobileprovision \
  --device 00008110-000A1B2C3D4E5F60
```

It checks the bundle id, team, profile expiry and the device UDID against the profile before touching
anything, signs nested code deepest-first, verifies each item and the finished bundle, then installs
with `devicectl` (Developer Mode must be on). `--dry-run` prints the plan and signs nothing.

**B. Sideloadly or AltStore** — drag the IPA in, enter your Apple ID, choose your team. A free
account's profile expires after 7 days, after which the app refuses to launch until it is signed
again; AltStore can refresh on a schedule, Sideloadly cannot.

## Checked on these files

- APK verifies under APK Signature Scheme v2 with one signer; the manifest reads `com.directly.app`,
  1.3.0, versionCode 4.
- IPA is `arm64` (device, not simulator), 1.3.0 build 4, no embedded profile, and `codesign` reports
  "code object is not signed at all".
- The signing helper completes an ad-hoc pass on this exact IPA, and the repackaged result passes
  `codesign --verify --deep --strict` with the entitlements and profile embedded.

**Not checked:** installation and first launch on physical hardware, whether Instagram still draws the
account chevron this build clicks, and the signed-in flows — inbox, opening a thread, sending, going
back. Those need a phone and a session. If something breaks, `docs/09-test-plan.md` §5 lists the
handful of observations that actually change the code.
