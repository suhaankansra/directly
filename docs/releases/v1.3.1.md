Directly opens Instagram straight into your DMs and takes away the feed, Reels and Explore. Watch the
reel a friend sent, then stop.

This release is two bugs people hit on iPhone, both of them the app quietly doing something else.

**It stopped leaving for facebook.com.** Every tap waited on a single test — "is this
`www.instagram.com`?" — and anything else was handed to Safari. Two things answer no to that test:

- **Facebook's sign-in dialog.** "Continue with Facebook" navigates to `facebook.com/…/dialog/oauth`.
  Safari did the sign-in and kept the cookies, so you came back still signed out, tapped again, and
  went round again. A web view can only sign in with cookies it holds itself, so Directly no longer
  hands this to Safari: it says that Facebook sign-in cannot finish here and to use your Instagram
  username and password.
- **Instagram's own link shim,** `l.instagram.com/?u=<where you are actually going>`. Because it is
  not `www.instagram.com`, a link a friend sent left the app — and when the link was a Facebook page,
  that was the trip you saw. The shim is now unwrapped and the real destination is judged by the same
  route rules as any other link.

Other sites still open in Safari, and ordinary Facebook links still do. Every `*.instagram.com` address
now stays in the app, which also means the Accounts Center reached from the Activity tab no longer
throws you out. Links starting `javascript:`, `data:` or `file:` are refused outright instead of being
passed to the system to open.

**The Profile tab stopped loading the inbox.** Without a known handle there is no path to build, and
the tab quietly went to `/direct/inbox/` — plausible-looking and useless. It now asks the page for the
profile link it is already showing, so it opens your profile; when there is genuinely no such link on
screen it says `Your profile link isn’t on this screen` instead of pretending. Lock → View profile
uses the same path.

## What this build cannot do

- **Facebook sign-in.** Not a limitation Directly can lift: the session would have to land in Safari's
  cookie store, which this app never sees. Use your Instagram username and password.
- **No alerts while the app is closed.** A `WKWebView` cannot receive web push, so a banner appears
  only while Directly is running. Background alerts would mean a server holding your session.
- **No instant switching between stored accounts.** One web view, one cookie jar, one session.

## Android

1. Download the APK on the phone, or transfer it there.
2. Allow installs from the browser or file manager when Android asks.
3. Install. Package `com.directly.app`, version 1.3.1, versionCode 5, target SDK 36.

Signed with the Android debug key, which is what makes sideloading possible. That is not a Play Store
upload key, so this build will never arrive through the Play Store.

## iOS

The IPA is built with `CODE_SIGNING_ALLOWED=NO`: a real `arm64` device binary with no signature,
because a certificate does not belong in CI. iOS refuses to install it until it carries a signature
from a team the device trusts.

**A. Sign it on your Mac** — needs a Development or Ad Hoc profile that already lists the device:

```bash
tools/resign-ipa.sh ~/Downloads/directly-v1.3.1-unsigned.ipa \
  --profile ~/Downloads/Directly.mobileprovision \
  --device 00008110-000A1B2C3D4E5F60
```

It checks the bundle id, team, profile expiry and the device UDID against the profile before touching
anything, signs nested code deepest-first, verifies each item and the finished bundle, then installs
with `devicectl` (Developer Mode must be on). `--dry-run` prints the plan and signs nothing.

**B. Sideloadly or AltStore** — drag the IPA in, enter your Apple ID, choose your team. A free
account's profile expires after 7 days, after which the app refuses to launch until it is signed
again; AltStore can refresh on a schedule, Sideloadly cannot.

## Notes

- The Facebook and profile-link fixes are reasoned from the code path and covered by unit tests, not
  reproduced on a device — no phone with a live session was in the loop. If the redirect persists,
  say whether facebook.com opened in Safari or inside the app; that distinction decides the next step.
- The DM badge and the alert are local. Nothing arrives while the app is closed.
- A reel opened from a conversation stays on that reel; swiping up or pressing next does nothing.
- Independent project, not affiliated with Instagram or Meta.
