Directly opens Instagram straight into your DMs and takes away the feed, Reels and Explore. Watch the
reel a friend sent, then stop.

This is the first published build: the app shell, the shared route rules and the in-page script that
hides the feed, Reels and Explore.

## Android

1. Download the APK on the phone, or transfer it there.
2. Allow installs from the browser or file manager when Android asks.
3. Install. Package `com.directly.app`, version 0.1.0, target SDK 36.

It is signed with the Android debug key, which is what makes sideloading possible. That is not a
Play Store upload key, so this build will never arrive through the Play Store.

## iOS

The IPA is built with `CODE_SIGNING_ALLOWED=NO`: a real `arm64` device binary with no signature,
because a certificate does not belong in CI. iOS refuses to install it until it carries a signature
from a team the device trusts. Two ways:

**A. Sign it on your Mac** — needs a Development or Ad Hoc profile that already lists the device:

```bash
tools/resign-ipa.sh ~/Downloads/directly-v0.1.0-unsigned.ipa \
  --profile ~/Downloads/Directly.mobileprovision \
  --device 00008110-000A1B2C3D4E5F60
```

It checks the bundle id, team, profile expiry and the device UDID against the profile before
touching anything, signs nested code deepest-first, verifies each item and the finished bundle, then
installs with `devicectl` (Developer Mode must be on). `--dry-run` prints the plan and signs nothing.

**B. Sideloadly or AltStore** — drag the IPA in, enter your Apple ID, choose your team. A free
account's profile expires after 7 days, after which the app refuses to launch until it is signed
again; AltStore can refresh on a schedule, Sideloadly cannot.

## Checked on these files

- APK verifies under APK Signature Scheme v2 with one signer; the manifest reads `com.directly.app`,
  0.1.0, versionCode 1.
- IPA is `arm64` (device, not simulator), 0.1.0 build 1, no embedded profile, and `codesign` reports
  "code object is not signed at all".
- The signing helper completes an ad-hoc pass on this exact IPA, and the repackaged result passes
  `codesign --verify --deep --strict` with the entitlements and profile embedded.

**Not checked:** installation and first launch on physical hardware, and the signed-in flows — inbox,
opening a thread, sending, going back. Those need a phone and an Instagram session. If something
breaks, `docs/09-test-plan.md` §5 lists the handful of observations that actually change the code.

## Notes

- No push notifications, by design: the DM badge and the alert are local, so nothing arrives while
  the app is closed.
- A reel opened from a conversation stays on that reel; swiping up or pressing next does nothing.
- Independent project, not affiliated with Instagram or Meta.
