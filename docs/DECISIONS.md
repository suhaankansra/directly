# DECISIONS

Running log. One entry per decision: what, why, when. Reversals get a new entry, not an edit.

| # | Date | Decision | Why |
|---|---|---|---|
| D001 | 2026-11-01 | Our product is named **Only Inbox** (bundle id `com.onlyinbox.app` proposed, pending Q10). *(Superseded by D027.)* | Clean-room requirement: never use the reference app's name, icon or assets. "Only Inbox" is descriptive, two words, and unlikely to collide in the App Store. |
| D002 | 2026-11-01 | Primary dev machine: **macOS** (arm64, Node 26, pnpm 12.14 already present). | Xcode is needed for the Safari Web Extension conversion and local device builds, so no EAS-cloud-only detour. |
| D003 | 2026-11-01 | iOS stack: **Expo (React Native) + TypeScript + react-native-webview**. | Accepted as the prompt's default; no contradicting evidence found. |
| D004 | 2026-11-01 | Web stack: **MV3 browser extension** (TypeScript, Vite/WXT build) **+ a small responsive static site**. | Accepted as default. A normal website cannot frame instagram.com or touch its DOM, and proxying sessions server-side is prohibited by the project's own rules. |
| D005 | 2026-11-01 | **One pnpm-workspace monorepo**, shared logic in `packages/core`. | Required by the prompt; the route rules, selectors and reel lock are the product and must not drift between iOS and web. |
| D006 | 2026-11-01 | Accent colour **#6C5CE7**. | Accepts the prompt default; close to the purple seen in the demo. |
| D007 | 2026-11-01 | Work proceeds **one phase per turn**, ending each turn with the phase report; next phase only on `next`. | Explicit instruction in the master prompt. |
| D008 | 2026-11-01 | Phase 1 produces **documentation only** — no scaffolding, no package installs. | Phase 1 says "write no code"; rule 5 says don't install packages that aren't in an approved phase plan. |
| D009 | 2026-11-01 | Product promise is read as **"no browsing"**, not literally "no non-DM surfaces": one item a friend sent is allowed, continuing from it is not. | The prompt's own one-sentence product says exactly this; the stricter reading would block a photo a friend DMs, which the reference build plainly allows. Pending user confirmation (Q12). |
| D010 | 2026-11-01 | iOS = native shell around Instagram mobile web in a WKWebView. Web = extension running on instagram.com. Both share `packages/core`. | Only lawful shapes that show a *logged-in* Instagram without us ever handling credentials. Iframing is impossible (`X-Frame-Options: DENY`), proxying and private APIs are prohibited or unsafe. Details: [02-architecture.md](02-architecture.md) §2. |
| D011 | 2026-11-01 | Blocked route → **redirect to `/direct/inbox/` plus a one-line toast**, never an interstitial. | Inbox is home; an interstitial taxes every mistap and reads as a broken app. |
| D012 | 2026-11-01 | Reels opened from anywhere are pinned to **one id**; any other reel/post id is blocked while pinned. Same rule for `/p/<id>/`. | Makes the promise uniform and explainable, and removes the need to distinguish "sent by a friend" from "reached some other way". |
| D013 | 2026-11-01 | **Stories blocked by default**, behind a toggle in the Lock tab. | A story session is the endless-tap surface the product exists to remove. Pending user confirmation (Q1). |
| D014 | 2026-11-01 | Profile pages **allowed**; grid scrolls, but a tapped tile opens one frozen item (Option A). | You looked the person up on purpose — intent, not discovery. Freezing a virtualised grid looks broken, and broken is worse than a profile you chose to visit. Pending user confirmation (Q3). |
| D015 | 2026-11-01 | Fourth tab = **P1: settings + logout now, focus-lock timer second**. | Matches the padlock metaphor, gives the tab a reason to exist, and the timer can later be monetised without a paywall rewrite. |
| D016 | 2026-11-01 | **One WebView reused across all tabs**, not one per tab. | Keeps one session and one cookie jar (no duplicate logins), halves memory, and guarantees a single source of truth for URL/tab state. Tab switches use `replaceState` so history doesn't accumulate dead entries; in-thread back still works. |
| D017 | 2026-11-01 | **Fail closed for routes, fail open for cosmetics.** Unknown route → blocked; broken cosmetic selector → nothing hidden. | A stale selector must never open the feed; an ugly app is recoverable, an un-openable one is not. |
| D018 | 2026-11-01 | Remote selector/route config is **pure data** (known keys → selector strings, pattern → verdict), with CSS and all logic bundled. | Chrome policy explicitly excludes JSON/CSS from "remotely hosted code" but rejects interpreters for remote commands; this stays on the legal side by construction. |
| D019 | 2026-11-01 | `/reels/<code>/` is treated as **one pinned item**, not the Reels tab: allowed only when `<code>` equals the pin. `/reels/` and `/reels/audio/*` stay blocked. | Instagram uses both `/reel/<code>` and `/reels/<code>` for a single item (03-findings §5 question 2). Blocking both would block a reel a friend sent — the one thing the product promises. A code id cannot open a feed. |
| D020 | 2026-11-01 | Do **not** spoof the user agent in the iOS WebView. | WKWebView already presents a mobile-Safari-like UA, so Instagram serves the mobile layout. A spoofed UA is a signal that invites the very anti-automation checks we cannot afford (risk R1/R6). |
| D021 | 2026-11-01 | Add `hostVerdict()`: the host layer blocks definite routes and allows a conditional one **only when the previous URL was a DM or a profile**. | The host cannot see a pin that layer 2 has not armed yet, so a naive table would block the reel a user tapped in a thread. Deep links and external redirects, where there is no such origin, stay blocked. |
| D022 | 2026-11-01 | Verify with a **local fixture** that mimics Instagram's mobile DOM and runs the real built script, instead of logging into Instagram. | Phase 3 forbids me from logging in; the fixture tests the guard, reel lock, cleanup and nav end-to-end in Chromium without any account or credentials. |
| D023 | 2026-11-01 | The page reports the signed-in username (`di:account`) so the Lock tab can show it; the host validates it as a username and never stores it. | Phase 8 asks for the logged-in account to be shown. Reading a profile link the page already renders is the least invasive way; the message is regex-limited and carries nothing else. |
| D024 | 2026-11-01 | One self-booting entry (`inpage/standalone.ts`) is what `dist/inpage.js` contains, so iOS and the extension run **the identical script**; the extension adds its own bootstrap only for settings and the options page. | One artifact, one behaviour. The alternative — a WebView-specific build — is how the two surfaces drift apart. |
| D025 | 2026-11-01 | The Lock tab is a **native overlay**, not a WebView route. | There is no Instagram route for settings, and a native screen can carry the switches, sign-out and the privacy text without touching the page. The WebView stays mounted underneath, so the session and history survive a visit to the Lock tab. |
| D026 | 2026-11-01 | D007 (one phase per turn) is **superseded for this run**: the user asked for all phases in one go. | Work continues through Phases 3–11, but every phase still ends in its own document, and the decision log stays append-only. |
| D027 | 2026-11-02 | Product renamed **Only Inbox → Directly** (supersedes D001). Applied everywhere: brand copy, `@directly/*` package scope, `com.directly.app` bundle id, `directly` URL scheme, `di-`/`di:` code namespace, and the GitHub repo. | "Only Inbox" was a placeholder. "Directly" is Instagram's own word for DMs, so it names the one surface left without explaining the product twice. Renaming the internal `oo-` namespace in the same pass avoids a codebase that is half-branded, and the log keeps D001 as written because reversals get a new entry, not an edit. |
| D028 | 2026-11-02 | Android ships from the same Expo app. Sign-out uses Instagram's own `/accounts/logout/` route and `WebView.clearCache`, and the `@react-native-cookies/cookies` dependency is **removed**; `decelerationRate` is passed as a number. | That cookie package's newest version (6.2.1) still calls `jcenter()` in its Gradle script, which Gradle 9 removed, so it cannot build at all — the two things it did are covered natively. A dependency that will not compile is worse than the logout route Instagram already provides. On Android the prop binding casts `decelerationRate` to `Double`, so the string `"normal"` crashed view creation with "String cannot be cast to Double". |
| D029 | 2026-11-14 | Cleanup spares **any sent post or reel** link inside a thread (`/p/`, `/reel/<id>`, `/reels/<id>`), not just `/p/`, and only while `allowReelsFromDms` is on. | The exemption was written for posts alone, so cleanup hid a `/reel/<id>` link a friend sent *before* the tap that arms its pin — the one thing the product promises was unreachable from a DM. Strict mode still hides it, because there it could never be opened. |
| D030 | 2026-11-14 | The reel lock cancels vertical gestures **inside the locked slide and its scroller**, not document-wide, and restores every `video.loop` it changed on disarm. | Document-wide cancellation also froze the comment sheet, the caption and the thread behind the modal, which §7 of 02-architecture.md explicitly wanted left alone. Leaving `loop = true` behind stopped the player firing `ended` on any later page that reused the element. If the slide selectors resolve nothing, the old wider net stays, so a broken selector cannot become a gesture bypass. |
